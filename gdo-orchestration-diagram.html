Architecture — Game Development OS

The GDO Orchestration Loop

Two halves, joined at one deliberate checkpoint: a design funnel only a human can advance, handing off into a per-ticket execution loop that gdo-orchestrator drives end to end — implement, review, merge, QA — on its own, until the epic is done or something genuinely needs a decision.

Who does what

Six agent types, each defined in .claude/agents/, each with only the tool access its role needs.

AgentRoleRuns
gdo-orchestratorDrives the whole per-epic loop — the only agent with its own tool access to spawn the other five.main checkout
gdo-implementerWrites the code, verifies it against the ticket's own acceptance criteria, commits, opens or updates the PR.isolated worktree
gdo-artistSame job, for an ART-NNN ticket — generates original placeholder art (checkerboard PNG / silent WAV), never third-party assets.isolated worktree
gdo-reviewerChecks out the real branch, re-verifies every criterion by running it, posts REQUEST_CHANGES findings as a PR comment.isolated worktree
gdo-qaRe-verifies on actual mainline post-merge, plus a scoped exploratory pass beyond the ticket's literal scope.isolated worktree
gdo-design-reviewerCritiques the GDD before MVP scoping unlocks. Design-time only — not part of the execution loop below the gate.isolated worktree

/gdo-setup isn't an agent — it's the one-time skill that installs and connects this framework to a project, run before any of the above ever gets spawned.
